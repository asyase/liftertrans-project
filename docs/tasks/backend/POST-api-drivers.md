# Task: POST /api/drivers — uue juhi lisamine

## Kirjeldus
ADMIN kasutaja saab lisada süsteemi uue juhi (vaade `DriverCreateEditView.vue`, rada `/drivers/new`). Backend salvestab juhi tabelisse `driver`.

Juhi lisamine **ei loo sisselogimiskontot** — DRIVER kontod (`user` tabel, väli `user.driver_id`) on eraldi teema ja siia taski ei kuulu.

**Vaste balsamic mockupis:** leht "LISA / MUUDA JUHTI", märkmed `docs/balsamic/notes/DriverCreateEditView-markmed.md`

**Seotud task:** `docs/tasks/backend/PUT-api-drivers-driverId.md` (juhi muutmine) — kasutab sama `DriverRequestDto`-d. Kumb task tehakse esimesena, see loob DTO; teine kasutab olemasolevat.

## Endpoint

`POST /api/drivers`

`DriverRequestDto.java` — request body:
```json
{
  "name": "Mart Tamm",
  "phone": "+3725551111",
  "email": "mart.tamm@liftertrans.ee",
  "active": true
}
```

| Väli | Tüüp | Kohustuslik | Valideerimine |
|---|---|---|---|
| `name` | String | jah | `@NotBlank`, `@Size(max = 150)` |
| `phone` | String | jah | `@NotBlank`, `@Size(max = 30)` |
| `email` | String | ei | `@Email`, `@Size(max = 150)` |
| `active` | Boolean | jah | `@NotNull` |

Response (200): NONE

**Veateated:**

| HTTP | errorCode | message |
|---|---|---|
| 400 | `INCORRECT_INPUT` | "name: must not be blank" (esimese vigase välja nimi + valideerimisteade) |

## Seotud tabelid
- `driver` (`id`, `name`, `phone`, `email`, `active`)

## Implementatsiooni märkused

1. **Andmebaas — `driver.id` genereerimine.** `docs/database/2_create.sql`-is on praegu `driver.id int NOT NULL` ilma genereerimiseta, seega uue juhi id oleks `null` ja salvestamine kukub. Tee sama muudatus, mis tehti `job` tabelile (LIF-65):
   ```sql
   -- id genereerib andmebaas uue juhi lisamisel. BY DEFAULT, et 3_import.sql saaks id-d ise ette anda
   id int  GENERATED BY DEFAULT AS IDENTITY NOT NULL,
   ```
   `3_import.sql` lõpus olev `setval(pg_get_serial_sequence('driver', 'id'), ...)` hakkab siis tööle ja järgmine id jätkub importitud juhtide järel. Käivita skriptid lokaalselt uuesti (1 → 2 → 3 ühes psql seansis, port 5433) — **see kustutab lokaalsed andmed**.
   > Märkus: `2_create.sql` muudatus mõjutab kogu tiimi — anna teistele teada, et nad peavad pärast pull'i skriptid uuesti käivitama.
2. **Entity** `Driver.java` — lisa `id` väljale `@GeneratedValue(strategy = GenerationType.IDENTITY)` (vt `Job.java`).
3. **DTO** — loo `dto/DriverRequestDto.java` (ilma `driverId`-ta), valideerimisannotatsioonidega nagu tabelis ülal (kui PUT task on juba tehtud, on DTO olemas).
4. **Mapper** `DriverMapper.java` — lisa meetod `Driver toDriver(DriverRequestDto driverRequestDto)`, `id` ignoreeritakse (`@Mapping(target = "id", ignore = true)`).
5. **Service** `DriverService.java` — meetod `addDriver(DriverRequestDto driverRequestDto)`: mapper → `driverRepository.save(driver)`.
6. **Controller** `DriverController.java` — `@PostMapping("/drivers")`, parameeter `@RequestBody @Valid DriverRequestDto driverRequestDto`, lisa `@Operation` ja `@ApiResponses` (200 ja 400) nagu teistel endpointidel.

## Vastuvõtu kriteeriumid
- [ ] `driver.id` genereeritakse andmebaasis automaatselt; `3_import.sql` laeb endiselt ilma veata.
- [ ] `POST /api/drivers` korrektse body'ga tagastab 200 ja uus juht tekib tabelisse `driver` uue id-ga (importitud andmetega järgmine id = 4).
- [ ] Uus juht on nähtav `GET /api/drivers` vastuses.
- [ ] Tühja `name` või `phone` korral tagastatakse 400 `INCORRECT_INPUT` ja andmebaasi midagi ei salvestata.
- [ ] Vigase e-posti (nt `"vale"`) korral tagastatakse 400 `INCORRECT_INPUT`.
- [ ] `email` võib puududa (`null`).
- [ ] Endpoint on Swaggeris kirjeldatud.
